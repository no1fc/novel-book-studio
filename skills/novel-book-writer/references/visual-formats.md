# 같은 이야기의 세 가지 시각 형식

공통 `character-bible.json`과 이야기 원장을 공유하되 형식마다 장면 계획을 별도로 만든다. 내용과 얼굴은 보존하고 독자가 읽는 호흡은 각색한다. `illustrated-novel`은 소설+정지 애니메이션풍 그림이며 실제 애니메이션 영상 기능은 없다.

## 삽화 소설

소설의 문장과 심리가 중심이다. 장면 앵커 뒤에 독립 오른쪽 전면 그림을 넣는다. 그림 없이도 본문에서 사건·원인·선택을 이해할 수 있어야 한다. 그림에서만 범인의 단서나 해결 규칙을 새로 제시하지 않는다. 세부 절차는 [production-loop.md](production-loop.md).

## 웹툰

각 화를 세로 스크롤 대본으로 각색한다. 패널별 장소·시점·행동 한 순간·대사·시선·위아래 연결과 여백의 목적을 적는다. 도입의 상황 제시, 행동/반응, 감정의 멈춤, 마지막 전환을 패널로 설계한다. 지문 전체를 그림 위에 붙이지 않는다. 전투에서는 준비·타격·결과를 읽는 순서로 나눠 공간 관계가 바뀌지 않게 한다.

`build_visual.py`는 `format: webtoon` 계획에서 검수된 패널을 순서대로 세로 합성한다. 현재 로컬 기본값은 폭 800px, 구간 높이 최대 2400px, 패널 간격 80px이며 업로드 플랫폼 규격을 뜻하지 않는다. 플랫폼 배포를 요청받으면 현재 공식 규격을 확인해 설정한다. 출력은 스크롤 `index.html`, 번호순 PNG, `manifest.json`이다.

구간 분할은 패널 사이에서만 한다. 단일 패널이 제한보다 길면 도구가 거부하므로 대본/구도를 나누거나 목표 규격을 바꾼다. 말풍선과 얼굴을 자르는 임의 슬라이스를 만들지 않는다. 큰 장면의 스크롤 리듬은 직접 미리보기로 확인한다.

## 만화책

페이지 넘김과 읽기 방향부터 정한다. 기본 한국어 LTR이며 RTL이 명시되면 그 방향으로 콘티를 설계한다. `layout.pages`의 배열은 페이지 순서, 각 `panels` 배열은 읽는 순서다. 좌표 `rect`는 페이지 전체 대비 `[x,y,width,height]` 비율이다. 도구는 겹침/페이지 넘침을 거부하지만 복잡한 구도의 읽는 순서까지 자동 판단하지 않는다.

한 페이지에 너무 많은 설명을 넣지 않는다. 일반 장면은 목적에 맞는 수의 패널, 큰 충돌·발견은 큰 패널이나 전면 페이지를 사용한다. 동일한 원본을 잘라 붙여 사건이 진행되는 척하지 않는다. 각 패널을 본문의 시간·공간·인물 상태와 대조한다.

`format: comic` 출력은 검색 가능한 대사가 있는 A5 `comic.pdf`, 150dpi 페이지 PNG, 번호순 PNG의 `comic.cbz`, `manifest.json`이다. LTR/RTL 선호는 PDF 메타데이터에 기록하며 패널 좌표 자체를 자동 반전하지 않는다. 인쇄용 도련·CMYK·등표지·출판사 규격은 별도 작업이다.

## 대사와 효과음

그림 원본은 텍스트 없이 생성하고 `dialogue`에 화자, 실제 한글 대사, 이미지 기준 사각형을 둔다. 말풍선·지문은 후속 조판하여 오자와 한글 깨짐을 확인한다. 현재 렌더러는 둥근 사각형 말풍선을 지원하며 꼬리/손글씨 효과음 디자인은 자동 생성하지 않는다. 필요 시 해당 요소를 별도 디자인하고 최종 검수한다.

말풍선은 얼굴·손·충돌점·복선을 가리지 않아야 한다. 도구는 대사가 지정 사각형 안에 들어오는지 검사한다. 줄일 때 의미를 보존하고, 읽을 수 없을 만큼 글자를 작게 만들지 않는다. 대사 순서와 화자 연결은 최종 그림에서 직접 확인한다.

## 전달과 재개

공통 캐릭터 기준, 형식별 원고/패널 대본, 계획 JSON, 생성 프롬프트, 그림 원본, 검수 기록, 최종 파일을 함께 보관한다. 파일 해시와 자동 검사 통과, 실제 시각 검수, 사람 독자 평가는 구분한다. 재개 시 `progress.md`와 `story_project.py status`를 읽고 미완료 지점부터 계속한다. 다른 형식도 만들 수 있게 해 달라는 요청만으로 모든 형식의 전체 작품을 동시에 제작하지 않는다.
