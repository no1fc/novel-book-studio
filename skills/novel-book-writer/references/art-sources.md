# 그림을 마련하는 경로

이 스킬의 스크립트는 그림을 생성하지 않는다. 조판하고 검증할 뿐이다. 표지·삽화·패널 그림은 아래 경로 중 **지금 환경에서 실제로 되는 것**으로 마련하고, 그림마다 어느 경로를 썼는지 `book-design.md`에 적는다.

| 경로 | 잘 되는 것 | 안 되는 것 |
|---|---|---|
| 1. 코드로 그리기 | 풍경·사물·상징·문양·추상 구성, 실루엣·뒷모습·원경의 인물 | 얼굴과 표정이 읽히는 인물, 애니메이션풍·실사풍 작화 |
| 2. 외부 제작 반입 | 사용자가 다른 도구나 사람에게 맡겨 만든 모든 그림 | 이번 세션 안에서 바로 완성하기 |
| 3. 이미지 생성 도구 | 현재 도구 목록에 실제로 보이는 생성 도구가 있을 때 | 도구가 없는데 있다고 가정하기 |

## 어느 경로를 쓰는가

- **표지:** 그림이 어울리면 경로 1로 그린다. 글자만으로 충분하면 [cover-design.md](cover-design.md)의 타이포그래피 표지 구성을 고른다. 어느 쪽이든 완성된 표지가 나온다.
- **화풍을 지정하지 않은 삽화:** 경로 1로 그려 책을 완성한다. 인물은 실루엣·뒷모습·원경·손과 사물로 구도를 잡는다. 인물이 나오는 삽화를 요청받았다면 시작할 때 한 번 알린다. "인물은 얼굴 없이 실루엣과 원경으로 그린다. 얼굴이 보이는 그림을 원하면 말해 달라." 답을 기다리지 않고 진행한다. 전달할 때 '코드로 그린 벡터 그림'임을 밝히고, 다른 그림으로 바꾸고 싶을 때를 위해 요청서(경로 2)를 함께 남긴다.
- **얼굴이 보이는 인물, 애니메이션풍·실사풍, 웹툰·만화:** 경로 2가 기본이다. 작업을 시작할 때 한 번 알린다. "이 환경에서는 그 화풍의 그림을 만들 수 없어, 원고와 조판을 끝내고 그림 제작 요청서를 남기겠다. 실루엣 중심의 코드 그림으로 대신해도 되면 말해 달라." 답을 기다리지 않고 집필을 진행한다.
- **경로 3:** 도구 목록에서 이미지 생성 도구를 직접 확인했을 때만 쓴다. 호출마다 비용이나 크레딧이 드는 도구는 사용자가 승인한 뒤 쓴다. 참조 이미지를 입력으로 받지 못하는 도구로는 캐릭터 일관성을 보장한다고 말하지 않는다.

## 경로 1: 코드로 그리기

SVG를 직접 작성해 `scripts/render_art.py`로 PNG를 만든다. 결과 PNG는 `--cover-image`나 계획의 `image` 경로에 그대로 쓴다.

```bash
python scripts/render_art.py --svg art/cover.svg --output art/cover.png --size a5
```

`--size`는 `a5`(1748×2480), `a5-draft`, `webtoon`, `square` 또는 `가로x세로` 픽셀이다. Chromium 계열 브라우저가 필요하며 없으면 오류로 알려 준다.

1. **자리부터 정한다.** `viewBox="0 0 1480 2100"`(A5 비율)로 잡는다. 제목이 놓일 면적, 시각적 중심 하나, 가장자리 5% 안전 영역을 먼저 정한다. 삽화는 맞은편 본문 발췌의 한 순간을 고른다.
2. **층으로 쌓는다.** 배경 그라데이션 → 원경 → 중경 → 근경 실루엣 → 광원과 번짐(`feGaussianBlur`) → 종이 질감(`feTurbulence`를 낮은 불투명도로). 색은 책 팔레트의 HEX에서 3~5개만 쓴다.
3. **글자를 넣지 않는다.** `<text>` 요소 없이 그린다. 제목·대사는 빌더가 실제 한글로 조판한다.
4. **렌더링한 PNG를 직접 열어 본다.** SVG 코드만 읽고 완성으로 판단하지 않는다. 책 크기 확대본과 폭 120~160px 축소본에서 중심이 읽히는지, 제목 자리가 비어 있는지, 의도하지 않은 빈 면이나 잘림이 있는지 본다. 고칠 점을 정해 2~3회 다시 그린다.
5. **원본을 남긴다.** `.svg`와 `.png`를 함께 `art/`에 보관한다. 계획의 `prompt`는 코드로 그릴 때도 외부 도구에 그대로 줄 수 있는 문장으로 적는다. 그래야 요청서를 교체용으로 쓸 수 있다. 같은 인물·장소가 여러 그림에 나오면 같은 실루엣 `<symbol>`과 색을 다시 쓴다. 인물이 보이는 장면이 계획에 있으면 실루엣 기준 시트를 먼저 그려 `reference`로 고정한다.

코드 그림을 'AI 생성 삽화'나 사람 작가의 작화라고 부르지 않는다. 특정 상업 표지나 현역 작가의 고유 화풍을 베끼지 않는다.

## 경로 2: 요청서를 남기고 그림을 반입

1. 원고에 `[[art:id]]` 앵커를 두고 `production.json`에 장면·인물 상태·프롬프트·저장 경로를 채운다. 그림 파일은 아직 없어도 된다.
2. 요청서를 만든다. 그림마다 저장 경로, 프롬프트, 첨부할 기준 그림이 적힌다.

   ```bash
   python scripts/visual_assets.py export-prompts --plan production.json --output art-requests.md
   ```

3. 지금 전달할 수 있는 책을 만든다. 사용자에게 건네는 책은 `build_book.py --text-only`로 만든 삽화 없는 독서본이다. `--visual-plan production.json --allow-pending-art` 배치 초안은 그림이 들어갈 쪽과 맞은편 본문을 확인하는 작업용이다. 둘 다 최종 삽화본이 아니라고 밝힌다. 기준 그림이 아직 없는 인물의 `reference.sha256`은 빈 문자열로 둔다.
4. 사용자에게 요청서 경로와 순서를 알린다. 캐릭터 기준 그림을 먼저 만들고, 장면을 만들 때 그 기준 그림을 첨부해야 한다. 표지용 프롬프트는 `book-design.md`에 둔다.
5. 그림이 들어오면 `story_project.py status`의 `missing_art`로 빠진 파일을 확인한다. 기준 그림의 해시를 갱신하고, 그림을 직접 본 뒤 [production-loop.md](production-loop.md)의 검수·최종 조판 순서를 따른다.

이미 있는 그림을 바꿀 때는 새 파일명(`-v2`)으로 저장하고 계획의 `image`나 원장의 `reference` 경로와 해시를 고친 뒤 다시 검수한다. 앞 판을 덮어쓰지 않는다.

사용자가 준 그림도 같은 검수를 거친다. 권리 관계를 알 수 없는 그림을 공개 저장소에 넣지 않는다.

## 보고

그림마다 `경로 / 파일 / 직접 본 검수 내용`을 적는다. 만들지 못한 그림은 미완료로 적고 요청서 위치를 남긴다. 그림을 만들지 않았는데 만들었다고 쓰지 않는다. 요청받은 삽화 수를 표지나 캐릭터 시트로 대신 채우지 않는다.
