# 요청문 만들기: 막연한 구상에서 집필 요청까지

사용자가 '뭘 써야 할지 모르겠다', '어떻게 요청하면 되나', '이 양식을 채워 달라', '소재를 추천해 달라'고 할 때 사용한다. 결과는 사용자가 고쳐 쓰거나 그대로 복사할 수 있는 **소설 제작 요청문**이다. 요청문 작성만 요청했다면 집필·이미지 생성·PDF 제작을 시작하지 않는다. '정해서 바로 써 줘'처럼 제작까지 맡겼다면 짧게 가정을 밝히고 집필 단계로 이어간다.

## 대화를 여는 방법

먼저 이미 알려 준 장르·소재·분량·금지 요소·산출물을 추린다. 미정인 항목과 제안한 기본값을 구분하고 확정된 취향처럼 말하지 않는다. 모든 항목을 설문처럼 묻지 않는다.

- **방향이 전혀 없을 때:** 독서 경험이 다른 후보 2~3개를 제시한다. 각 후보는 `장르 / 구체적인 주인공과 곤란 / 분위기`를 한두 문장으로 쓴다. 추천 하나와 짧은 이유를 붙이고, 가장 끌리는 방향 하나만 묻는다. 장르 용어를 모르는 사람도 고를 수 있게 설명한다.
- **장르만 있을 때:** 그 장르 안에서 배경·갈등이 다른 소재 후보를 제시한다. 예를 들어 추리는 실종 조사, 밀실의 알리바이, 과거 사건 재조사의 독서 경험을 구별한다. 범인·결말을 미리 공개할 필요는 없다.
- **조건과 원하는 산출물이 충분할 때:** 추가 질문 없이 완성된 요청문을 만든다. 배경·시점 같은 미정 항목은 '제안, 변경 가능'으로 표시하거나 제작자가 정하도록 맡긴다.
- **사용자가 전부 추천해 달라고 할 때:** 추천안 하나로 요청문을 완성한다. 선택을 받는다는 이유로 같은 질문을 반복하지 않는다.
- **조건이 충돌할 때:** 충돌하는 조건과 결과 차이를 짧게 설명하고 결정에 필요한 질문만 한다. 예: '본문 정확히 45쪽'과 '분량 조정 없이 기존 원고 전부 유지'.

질문이 필요하면 한 번에 1~3개 이내로 묶는다. 핵심은 읽고 싶은 감정, 피하고 싶은 요소, 분량·결과물이다. 이름·시점·장 수·색상까지 처음부터 모두 확정할 필요는 없다. '모르겠으니 추천해 줘'를 유효한 답으로 받아들인다. 도구가 없는 환경에서도 일반 대화로 동작해야 한다.

## 페이지 수를 요청받았을 때

판형, 포함 범위, 목표/정확한 쪽수 여부, 초과 허용을 그대로 보존한다. 예를 들어 '표지·목차 제외, 프롤로그 포함 A4 45쪽, 필요하면 증가 가능'을 'A5 45쪽'이나 고정 글자 수로 바꾸지 않는다. 속표지 같은 앞부분의 계산도 요청문에서 분명히 한다.

쪽수는 글꼴·크기·행간·여백에 따라 달라지므로 실제 조판으로 확인하도록 적는다. 글자 수를 제시할 때는 잠정 추정임을 표시한다. 표지·빈 페이지·큰 글자·과도한 여백으로 본문 목표를 채우지 않는다. 기본 조판 제안은 한글 명조 11pt, 줄간격 1.6~1.75, 여백 20~25mm이며 사용자 조건을 우선한다.

현재 번들 빌더는 A5 고정이다. A4 등 다른 판형의 요청문을 만드는 것은 가능하지만 지원되지 않는 CLI 옵션을 꾸며 내지 않는다. **실제 제작 때 요청한 판형을 지원하도록 조판을 수정하거나 적합한 도구를 사용하고 PDF 크기를 검증한다.** 요청문 작성만으로 판형 지원 구현이 완료된 것은 아니다.

## 최종 응답 형태

짧은 추천 이유 또는 가정 설명 뒤, **독립적으로 복사해 사용할 수 있는 코드 블록 하나**를 제공한다. '위에서 정한 설정' 같은 대화 의존 표현과 채우지 않은 필수 빈칸을 남기지 않는다. 다음 항목 중 요청에 필요한 것만 넣는다.

```text
novel-book-writer 스킬을 사용해 [요청 범위]를 진행해 줘.

장르:
배경과 핵심 갈등:
독자층과 분위기:
분량·판형·쪽수 계산 범위·초과 허용:
보존할 조건과 피할 요소:

실제 열람 가능한 같은 장르 자료의 기법을 참고하되
고유한 인물·사건·반전을 복제하지 않는다.
인물의 행동 이유와 사건의 인과관계를 본문에서 이해할 수 있게 쓴다.
완성 후 본문만 읽는 이해도 검사를 하고, 누락은 본문에서 수정한다.

[요청된 경우] 원고에 맞는 표지·목차·본문 PDF를 제작하고
실제 페이지 크기·본문 쪽수·누락·한글·목차·시각 배치를 검증한다.
[요청된 경우] AI 그림은 사용 가능한 생성 도구로 제작하며,
도구가 없으면 생성했다고 주장하지 않고 미완료 범위를 밝힌다.

요청한 원고·파일과 실제 참고·검토 기록을 전달한다.
스포일러가 있는 설계·검토 기록은 독자용 본문에서 분리한다.
```

이는 작성용 골격이다. 사용자에게 전달할 때 대괄호와 항목을 실제 조건으로 채우고 불필요한 부분은 제거한다. 짧은 장면 요청에는 책 한 권의 설계·PDF를 추가하지 않는다. 소설 집필 요청에는 사용자가 명시적으로 제외하지 않은 기본 책 제작 흐름을 적용한다.

장르별 핵심 기준은 2~4개만 선별한다. 추리라면 사전에 제시한 단서·알리바이·동기와 수법의 회수, 스릴러라면 위험의 상승·행동의 대가·긴장과 이완처럼 실제 독서 경험을 바꾸는 조건을 넣는다. 모든 장르에 범인·희생·반전을 강요하지 않는다.

## 전달 전 확인

원래 조건과 최종 요청문을 대조한다. 빠진 조건, 새로 강제한 취향, 미정인데 확정한 설정이 없는지 확인한다. 요청문만 요청했으면 여기서 끝낸다. 사용자가 '이대로 제작해 줘'라고 하면 요청문을 브리프로 삼아 기존 집필 절차를 진행하고 확정한 내용을 다시 묻지 않는다.
